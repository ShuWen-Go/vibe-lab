# 结构化输出 prompt 模板 v1

> 来源：W2 · D4 三轮实验（2026-09-21），实测 15 次
> 用途：D5 `index.html` 的 system 输入框默认值 · D6 后端引擎 · **S2 / V1 的结构化卡片引擎**
> 实验脚本：`json-demo.mjs`

---

## 一、什么时候用

| 适用 | 不适用 |
|---|---|
| **抽取型任务**：从一段文字里抽出固定字段（摘要 / 要点 / 金句 / 待办） | **开放式生成**：诊断、方案、起名（这类需要推理，成本的大头在 `reasoning`，不在输出） |
| 输出要**被程序消费**（前端渲染、入库、后续逻辑判断） | 输出只给人看、格式无所谓 |

---

## 二、模板正文（`system` 内容，整体复制）

```text
【角色】
你是信息提取器。从用户给出的文字里提取信息，只输出一个 JSON 对象。

【只输出 JSON】
- 不要任何开场白、说明文字或结尾总结
- 不要用小标题、加粗、列表符号等 markdown 排版
- 不要用代码块标记把 JSON 包起来
- 输出的第一个字符必须是 {，最后一个字符必须是 }

【字段规范】必须包含且只包含这 4 个字段：
- summary：字符串。用一句话概括全文主旨，不超过 60 字。
- points：字符串数组。3 到 6 条关键信息，每条不超过 30 字。
- quotes：字符串数组。从原文【逐字摘录】最有代表性的话，不要改写、不要换词、不要加标点；找不到合适的就给空数组。
- todos：字符串数组。原文提到的下一步要做的事；没有就给空数组。

【书写要求】
- 键名和字符串值都用半角双引号
- 字符串内部不要换行；要分条就拆成数组元素
```

> ⚠️ **贴代码时注意**：往 `.mjs` 的**模板字符串**（反引号包裹）里贴时，正文中**不能出现反引号**，`${` 同理，否则字符串提前终止、直接语法报错。
> 上面的"不要用**代码块标记**把 JSON 包起来"是刻意的措辞 —— **不要真的把那三个反引号符号敲进去**。
> 改完先自检语法：`node --check json-demo.mjs`（只查语法、不发请求、不花钱）。

## 三、参数配置

| 参数 | 值 | 理由 |
|---|---|---|
| `temperature` | `0` | 结构化字段名不能飘；温度高会让键名/措辞都飘 |
| `max_tokens` | `4000` | `reasoning` 会吃掉额度（实测 0–563，重尾）；额度太小照样出空 JSON |
| `stream` | `false` | 机器在等，不需要打字机效果（流式还带来 ~300 字符/token 的帧流量开销） |

## 四、few-shot（可选 —— 不是达标的必要条件）

**本轮实测结论：加格式约束（②）就已经 7/7 全绿；few-shot 是"补充手段"，不是"达标必需"。**
当规则已经能把格式描述清楚时（四字段这种简单结构），它的**增量接近 0**；它的适用场景是"**格式复杂到规则难以描述清楚**"时。

**结构**（标准对话结构，不是在 system 里加个例子）：

```
system    ：上面的提取规则
user      ：示例输入（一小段，与真实素材无关）
assistant ：{"summary":"…","points":[…],"quotes":[…],"todos":[…]}
user      ：现在处理这一段：<真实素材全文>
```

**四条硬规则：**

1. 🚨 **示例素材必须与真实素材「零语义重叠」** —— 连主题词都不能撞。
   实测教训：示例写"控制台不报错"、真实素材里恰好有"不报错 ≠ 没问题" ⇒ **模型把示例里的句子抄进了真实输出**（**示例污染 / example leakage**）。换成"园艺"示例后污染消失 3/3。
   ⇒ **示例的"内容"会被模型当成可复用素材，不只是格式示范。**
2. **示例的 `quotes` 逐字取自示例输入** —— 示范"照抄"这个动作本身。
3. **示例的 `points` 取规范下限**（如 3 条）—— 示范"守着上限"（`points` 给超是最常见的违规）。
4. **示例里不带代码围栏** —— 否则模型会以为围栏是被允许的。

**成本**：每加一对 `user`/`assistant` 示例 ≈ **+104 prompt token**（实测 1176 → 1280，含消息外壳）。

## 五、代码侧判据（三层，缺一不可）

```js
// ① 结构层：是合法 JSON 吗（先剥掉可能被包上的代码围栏）
function checkJson(raw) {
  let t = raw.trim();
  const fenced = /^```/.test(t);
  t = t.replace(/^```(?:json)?\s*/i, '').replace(/```$/, '').trim();
  try { JSON.parse(t); return fenced ? '⚠️ 合法，但被代码围栏包住' : '✅ 合法 JSON'; }
  catch (e) { return '❌ 非法：' + e.message; }
}

// ② 内容层：quotes 真的是"逐字摘录"吗（去空白后子串比对）
const srcFlat = article.replace(/\s/g, '');
const parsed = JSON.parse(content);
for (const q of parsed.quotes) {
  console.log(srcFlat.includes(q.replace(/\s/g, '')) ? '  ✅ 照录：' + q : '  ❌ 改写：' + q);
}

// ③ 截断层：有没有被额度砍掉
if (data.choices[0].finish_reason !== 'stop') { /* 重试 / 降级 / 告警 */ }
```

> 🚨 **为什么三层都要**：
> - ① 只能证明"**结构合法**"，证明不了"**字段里装的东西对**"；
> - ② 才能抓出改写 / 示例污染（**肉眼会把"示例污染"误看成"改写"**）；
> - ③ `length` 是**静默失败**（付了钱、拿到空字符串，日志还干净），必须当可观测告警项。

## 六、已知边界（别把话说满）

| 边界 | 说明 |
|---|---|
| **格式对齐 ≠ 内容对齐** | `checkJson` 全绿不等于字段内容达标（实测：结构 100% 合法，`quotes` 仍可能被改写或污染） |
| **`prompt` 锁不住 `reasoning`** | 正文跨样本稳定在 184–264（±18%），`reasoning` 却在 0–563 乱跳 ⇒ **成本波动只能靠任务设计压，不能靠字数限制** |
| **素材形态会"传染"** | 输入是 markdown ⇒ 输出容易带 markdown。若素材含代码块，务必显式禁围栏 |
| **"最稳定"的结论有适用范围** | 本轮结论建立在「四字段 + 短素材 + `temp 0`」上；换更复杂的结构时，few-shot 的价值会上升 |
| **行首空白不是排版，是内容** | 给机器看的多行文本**一律顶格写**：`<textarea>` 里的换行与缩进会**原样跟着进 prompt**（D5 实测，每行 10 个空格 × 19 行）。本文件 `quotes` 那条已由「行首空格续行对齐」改为**单行** —— **模板与页面必须逐字一致，否则单变量对比不成立** |
